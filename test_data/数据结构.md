## 1. 递归的基本结构

递归函数是在函数执行过程中直接或间接调用自身的函数。

一个正确的递归算法通常需要两个核心要素：

1. 基准情形：满足特定条件时直接返回结果，不再继续调用自身。
2. 递归关系：把原问题缩小为规模更小的同构子问题，并向基准情形收敛。

基准情形用于终止递归。如果缺少基准情形，或者递归关系没有向基准情形收敛，程序可能不断调用自身，最终触发栈空间耗尽或运行时错误。

递归调用时，每一层尚未完成的调用都需要保存局部变量、参数和返回位置。这些信息通常保存在调用栈中，因此递归的空间开销与最大递归深度有关。

### 1.1 阶乘示例

阶乘可以写成一个递归关系：

```text
factorial(0) = 1
factorial(n) = n * factorial(n - 1)，其中 n > 0
```

其中 `factorial(0) = 1` 是基准情形，`factorial(n) = n * factorial(n - 1)` 是递归关系。

## 2. 迭代的基本结构

迭代通常使用循环结构重复执行一组操作。循环变量、累加器和当前处理位置等状态由程序显式保存和更新。

例如，计算阶乘的迭代版本会从 `1` 开始，依次乘入 `1` 到 `n` 的整数，并把结果保存在累加器中。

在常见的简单迭代算法中，不需要为每一次重复执行创建新的函数调用栈帧。但这不表示所有迭代算法的额外空间都是常数：如果算法显式创建数组、队列或栈，仍然需要额外的数据结构空间。

迭代需要一个能够结束的条件。如果循环条件永远不成立，程序可能进入无限循环。

## 3. 递归与迭代的区别

递归和迭代都可以用于重复执行逻辑，核心区别之一是中间状态由谁保存：

| 比较项 | 递归 | 迭代 |
|---|---|---|
| 状态保存 | 通常依赖函数调用栈 | 通常依赖循环变量和显式状态 |
| 基准/终止条件 | 基准情形 | 循环终止条件 |
| 简单循环的空间开销 | 通常较高，受递归深度影响 | 常见简单循环不需要额外调用栈 |
| 代码表达 | 适合具有自相似结构的问题 | 适合可以直接顺序推进的问题 |
| 风险 | 递归过深可能耗尽调用栈 | 终止条件错误可能无限循环 |

不能笼统地说递归一定比迭代快，也不能说迭代在所有情况下总内存都更少。实际复杂度取决于算法本身和使用的数据结构。

当问题可以自然分解为同构子问题时，递归往往更清晰；当问题的状态可以简单顺序推进，或者递归深度可能很大时，通常优先考虑迭代。

## 4. 二叉树的深度优先遍历

二叉树的前序、中序和后序遍历都属于深度优先遍历，它们的区别是访问根节点的时机。

- 前序遍历：先访问根节点，再遍历左子树，最后遍历右子树。
- 中序遍历：先遍历左子树，再访问根节点，最后遍历右子树。
- 后序遍历：先遍历左子树，再遍历右子树，最后访问根节点。

对于二叉搜索树，中序遍历会按照节点键值的升序得到序列。

树的递归遍历会使用调用栈。若树的高度为 `h`，遍历过程的最大递归调用栈深度与 `h` 成正比。

## 5. 时间复杂度和空间复杂度

时间复杂度描述算法执行时间随输入规模增长的增长率。空间复杂度描述算法除了输入本身之外，所需额外空间随输入规模增长的增长率。

递归算法的调用栈空间通常与其最大递归深度成正比。对于高度为 `h` 的树，递归遍历的调用栈空间复杂度通常记为 `O(h)`。

- 对于一棵高度平衡的二叉树，`h` 通常为 `O(log n)`。
- 对于一棵退化成链状结构的二叉树，`h` 为 `O(n)`。

迭代遍历并不必然使用 `O(1)` 空间。如果使用显式栈保存待访问节点，额外空间仍然与树高或节点数量有关。

## 6. 算法选择检查清单

选择递归或迭代时，可以依次检查：

1. 问题是否可以自然分解为同构子问题。
2. 递归深度是否可能过大。
3. 是否需要保存大量的中间状态。
4. 算法是否已有简单、可验证的循环终止条件。
5. 额外空间复杂度是否符合题目的限制。

这些检查项只用于辅助选择，不代表存在适用于所有题目的绝对规则。
